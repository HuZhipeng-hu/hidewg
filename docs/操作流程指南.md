# HideWG 操作流程指南（完整复现版）

本文档面向需要从零复现 HideWG 系统的任何人。按步骤执行即可完成从环境搭建到验证评测的全部流程。

---

## 一、系统架构总览

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  应用层       │     │  WireGuard   │     │  HideWG      │
│  ping/HTTP   │ ──► │  隧道加密     │ ──► │  WS 封装     │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                  │
                                           WSS:443 (TLS 1.3)
                                                  │
                                           ┌──────▼───────┐
                                           │  nginx 反代   │
                                           │  TLS 终止     │
                                           └──────┬───────┘
                                                  │
                                           WS:8443 (明文)
                                                  │
                                           ┌──────▼───────┐
                                           │  对端 HideWG  │
                                           │  WS 解封装    │
                                           └──────┬───────┘
                                                  ▼
                                           WireGuard → 应用
```

外层传输固定为 WebSocket-over-TLS，通过 nginx 反向代理实现标准 HTTPS 接入。Wireshark 抓包看到的是标准 WebSocket over TLS 1.3 流量，与普通 Web 应用无法区分。

端口分配：

| 组件 | 客户端 | 服务端 |
|------|--------|--------|
| WireGuard 监听 | 51820 | 51820 |
| HideWG 内层 (面向 WG) | 51830 | 51831 |
| HideWG 外层 (WS 监听) | — | 8443 |
| nginx (TLS 接入) | — | 443 |

## 三、WireGuard 基线环境搭建

### 3.1 服务端 WireGuard 配置

编辑 `/etc/wireguard/wg0.conf`：

```ini
[Interface]
Address = 10.7.0.1/24
PrivateKey = <服务端私钥>
ListenPort = 51820

[Peer]
PublicKey = <客户端公钥>
AllowedIPs = 10.7.0.5/32
```

生成密钥对：

```bash
# 生成服务端密钥对
SERVER_PRIV=$(wg genkey)
SERVER_PUB=$(echo "$SERVER_PRIV" | wg pubkey)
echo "服务端私钥: $SERVER_PRIV"
echo "服务端公钥: $SERVER_PUB"

# 生成客户端密钥对
CLIENT_PRIV=$(wg genkey)
CLIENT_PUB=$(echo "$CLIENT_PRIV" | wg pubkey)
echo "客户端私钥: $CLIENT_PRIV"
echo "客户端公钥: $CLIENT_PUB"
```

启动 WireGuard：

```bash
wg-quick up wg0
systemctl enable wg-quick@wg0
```

验证：

```bash
wg show wg0
# 应显示 interface、public key、listening port
```

### 3.2 客户端 WireGuard 配置

创建 `configs/wg-client.conf`：

```ini
[Interface]
PrivateKey = <客户端私钥>
Address = 10.7.0.5/32
ListenPort = 51820
MTU = 1280

[Peer]
PublicKey = <服务端公钥>
AllowedIPs = 10.7.0.1/32
Endpoint = 127.0.0.1:51830
PersistentKeepalive = 25
```

**关键点**：`Endpoint = 127.0.0.1:51830` 指向本机 HideWG 内层端口，而非服务端公网地址。

### 3.3 验证基线（不加 HideWG）

在配置 HideWG 之前，先验证原始 WireGuard 是否可用：

```bash
# 客户端临时指向服务端公网
# wg set wg0 peer <服务端公钥> endpoint 1.95.65.51:51820
# ping 10.7.0.1
```

确认 ping 通后，恢复 Endpoint 为 `127.0.0.1:51830`。

## 四、HideWG 配置

### 4.1 生成共享密钥

```bash
openssl rand -hex 16
# 输出示例: 661eacbc95a3016cd2c5e91361a303f6
```

两端使用同一个值。

### 4.2 服务端配置 (configs/server.yaml)

```yaml
# 共享密钥 —— 两端必须一致
shared_secret: 661eacbc95a3016cd2c5e91361a303f6
session_id: 0x48445747

# 内层：面向本地 WireGuard
inner_listen_host: 127.0.0.1
inner_listen_port: 51831

# 外层：面向公网（WS 监听端口，nginx 反代转发至此）
outer_listen_host: 0.0.0.0
outer_listen_port: 8443

# 对端地址（客户端在 NAT 后，首次通信后自动学习）
peer_host: 127.0.0.1
peer_port: 55820

# 本地 WireGuard 监听地址（必须与 wg show 显示的 listening port 一致）
wireguard_host: 127.0.0.1
wireguard_port: 51820

# 协议参数
max_fragment_payload: 1300
padding_buckets: [96, 128, 192, 256, 384, 512, 768, 1024, 1280]
padding_jitter_chance: 0.20
timing_jitter_ms: 2.5

# 填充模式: "adaptive" (桶+自适应) / "continuous" (连续分布)
padding_mode: adaptive
adaptive_padding: true
adapt_window_size: 128
adapt_strength: 0.6
bucket_jitter_sigma: 15.0
burst_timing: true

# AmneziaWG 借鉴
junk_count: 3
junk_min_size: 64
junk_max_size: 384
noise_prefix_min: 0
noise_prefix_max: 24
s4_padding_max: 48
cover_traffic: true
cover_rate_hz: 0.5
cover_burst_max: 2
cover_bidirectional: true
bucket_drift: 8

# 传输层：WebSocket-over-TLS（固定）
# TLS 证书路径（如使用自签名证书）
tls_certfile: .hidewg/tls/server.pem
tls_keyfile: .hidewg/tls/server-key.pem

# 状态输出
state_path: .hidewg/server_state.json
log_path: .hidewg/server_runtime.jsonl
pid_path: .hidewg/server.pid
```

### 4.3 客户端配置 (configs/client.yaml)

```yaml
shared_secret: 661eacbc95a3016cd2c5e91361a303f6
session_id: 0x48445747

# 内层：面向本地 WireGuard
inner_listen_host: 127.0.0.1
inner_listen_port: 51830

# 外层：面向公网
outer_listen_host: 0.0.0.0
outer_listen_port: 55820

# 服务端公网地址（通过 nginx:443 接入）
peer_host: 1.95.65.51
peer_port: 443

# 本地 WireGuard 监听地址
wireguard_host: 127.0.0.1
wireguard_port: 51820

# 协议参数（与服务端一致）
max_fragment_payload: 1300
padding_buckets: [96, 128, 192, 256, 384, 512, 768, 1024, 1280]
padding_jitter_chance: 0.20
timing_jitter_ms: 2.5

# 填充模式（与服务端一致）
padding_mode: adaptive
adaptive_padding: true
adapt_window_size: 128
adapt_strength: 0.6
bucket_jitter_sigma: 15.0
burst_timing: true

# AmneziaWG 借鉴（与服务端一致）
junk_count: 3
junk_min_size: 64
junk_max_size: 384
noise_prefix_min: 0
noise_prefix_max: 24
s4_padding_max: 48
cover_traffic: true
cover_rate_hz: 0.5
cover_burst_max: 2
cover_bidirectional: true
bucket_drift: 8

# WebSocket 路径
ws_path: /ws

state_path: .hidewg/client_state.json
log_path: .hidewg/client_runtime.jsonl
pid_path: .hidewg/client.pid
```

### 4.4 配置一致性检查

以下字段两端必须完全一致：

| 字段 | 说明 |
|------|------|
| `shared_secret` | 加密密钥来源 |
| `session_id` | 会话标识 |
| `max_fragment_payload` | 分片阈值 |
| `padding_buckets` | 填充桶 |
| `adaptive_padding` | 防御策略 |

以下字段各端独立：

| 字段 | 客户端 | 服务端 |
|------|--------|--------|
| `inner_listen_port` | 51830 | 51831 |
| `outer_listen_port` | 55820 | 8443 |
| `peer_host` | 服务端公网 IP | 127.0.0.1 |
| `peer_port` | 443 (nginx) | 55820 |
| `wireguard_port` | 51820 | 51820 |
| `ws_path` | /ws | — |
| `tls_certfile` | — | .hidewg/tls/server.pem |

## 五、防火墙与 nginx 配置

### 5.1 服务端

```bash
# Ubuntu/Debian (ufw)
ufw allow 443/tcp
ufw allow 8443/tcp
ufw reload

# CentOS/RHEL (firewall-cmd)
firewall-cmd --permanent --add-port=443/tcp
firewall-cmd --permanent --add-port=8443/tcp
firewall-cmd --reload

# 云服务器（以阿里云为例）
# 在安全组规则中添加：入方向 TCP 443 和 TCP 8443 允许
```

### 5.2 nginx 反向代理部署

```bash
# 1. 生成 TLS 证书（自签名测试用）
cd /opt/hidewg
./hidewg cert --cn <服务器IP> --output-dir .hidewg/tls

# 2. 复制 nginx 配置
cp configs/nginx-hidewg.conf /etc/nginx/sites-available/hidewg.conf
# 编辑配置：替换 server_name 和 ssl_certificate 路径

# 3. 启用站点
ln -s /etc/nginx/sites-available/hidewg.conf /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

生产环境推荐使用 Let's Encrypt：

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d your-domain.com
```

WireGuard 端口（51820）不需要对公网开放，因为 WireGuard 只与本机 HideWG 通信。

### 5.3 客户端

```powershell
# Windows 防火墙放行
netsh advfirewall firewall add rule name="HideWG Outer" protocol=udp dir=in localport=55820 action=allow

# 放行 WireGuard 子网 ICMP（服务端 ping 客户端需要）
netsh advfirewall firewall add rule name="WG ICMP In" protocol=icmpv4:8,any dir=in action=allow remoteip=10.7.0.0/24
```

## 十、常见问题排查

### 10.0 启动前自检清单

在启动 HideWG 之前，按以下清单逐项确认，可避免大部分 ping 不通的问题：

```bash
# ===== 客户端 (Windows) =====

# 1. 依赖已安装
python -c "import cryptography; print(cryptography.__version__)"
# 如报错 ModuleNotFoundError → pip install cryptography numpy

# 2. 无残留进程占用端口
netstat -ano | findstr "51830"
netstat -ano | findstr "55820"
# 如有占用 → taskkill //PID <PID> //F

# 3. 端口不在 Windows 保留范围内
netsh interface ipv4 show excludedportrange protocol=udp
# 确认 55820 和 51830 不在任何保留范围内
# 如果在 → 修改配置使用其他端口

# 4. WireGuard 已安装且可用
wg --version

# 5. 防火墙放行
netsh advfirewall firewall show rule name="HideWG Outer"
netsh advfirewall firewall show rule name="WG ICMP In"


# ===== 服务端 (Linux) =====

# 1. 依赖已安装
python3 -c "import cryptography; print(cryptography.__version__)"
# 如报错 → pip3 install cryptography

# 2. HideWG 全部模块已部署
ls /opt/hidewg/hidewg_app/
# 必须包含: __init__.py cli.py config.py protocol.py adapter.py
#            analysis.py verify.py state.py pcap.py transport.py ws.py
# 缺少文件 → scp -r e:/safewg/hidewg_app root@<服务器IP>:/opt/hidewg/hidewg_app

# 3. 无残留进程占用端口
ss -tlnp | grep -E '51831|8443'
# 如有占用 → kill <PID>

# 4. WireGuard 实际监听端口与配置一致
wg show wg0 | grep "listening port"
# 记录实际端口，确保 server.yaml 中 wireguard_port 与此一致
# 不一致 → sed -i 's/wireguard_port: <旧值>/wireguard_port: <实际值>/' /opt/hidewg/server.yaml

# 5. 防火墙/安全组放行 TCP 443 和 8443
ufw status | grep -E '443|8443'
# 或检查云平台安全组规则
```

### 10.1 WireGuard 握手失败

**症状**：`wg show` 无 `latest handshake`

**排查**：

```bash
# 1. 确认 HideWG 正在运行
ss -ulnp | grep 51831  # 服务端内层 (UDP)
ss -tlnp | grep 8443   # 服务端外层 (TCP/WS)
ss -tlnp | grep 443    # nginx TLS 接入
# 如果没有 → HideWG 未启动，先启动 HideWG

# 2. 检查客户端 Endpoint 是否正确指向 HideWG 内层
grep Endpoint configs/wg-client.conf
# 应为: Endpoint = 127.0.0.1:51830

# 3. 检查公钥是否匹配
# 客户端 peer 的 PublicKey 应等于服务端 wg show 显示的 public key

# 4. 检查共享密钥两端一致
# 客户端: grep shared_secret configs/client.yaml
# 服务端: grep shared_secret configs/server.yaml
# 两个值必须完全一致
```

### 10.2 单向通（客户端→服务端通，反向不通）

**原因**：客户端在 NAT 后，服务端无法主动连接客户端。

**排查**：

```bash
# 确认客户端有 PersistentKeepalive
grep PersistentKeepalive configs/wg-client.conf

# 确认客户端防火墙放行了 WireGuard 子网 ICMP
netsh advfirewall firewall show rule name="WG ICMP In"
```

### 10.3 HideWG 启动失败（端口占用）

**症状**：启动时报 `WinError 10013` 或 `Address already in use`

**原因**：上次运行的 HideWG 进程未正常退出，端口仍被占用。

```powershell
# Windows: 查找占用端口的进程
netstat -ano | findstr "51830"
netstat -ano | findstr "55820"

# 强制结束
taskkill //PID <找到的PID> //F

# 如果有多个残留进程，逐一结束
```

```bash
# Linux: 查找并结束
ss -tlnp | grep -E '8443|443'
kill <PID>
```

### 10.4 Windows 端口保留范围冲突

**症状**：启动时报 `WinError 10013`，但 `netstat` 未发现其他进程占用。

**原因**：Windows Hyper-V 会预留大段 UDP 端口范围，如果 HideWG 配置的端口落在保留范围内，即使没有进程占用也会被拒绝。

```powershell
# 查看所有 UDP 端口保留范围
netsh interface ipv4 show excludedportrange protocol=udp
```

典型保留范围示例：

```
协议 tcp 端口排除范围
-------------------------------
    起始端口    结束端口
    ----------    --------
        55865         55964
        ...
```

**解决方案**：将 HideWG 端口配置在保留范围之外。例如保留范围 55865-55964，则使用 55820/55821 是安全的。修改 `configs/client.yaml` 和 `configs/server.yaml` 中的 `inner_listen_port`、`outer_listen_port`，确保不在任何保留范围内。

### 10.5 服务端配置 wireguard_port 不匹配

**症状**：HideWG 服务端启动成功，但 WireGuard 握手始终无法完成。

**原因**：`server.yaml` 中 `wireguard_port` 与 WireGuard 实际监听端口不一致。HideWG 将解密后的包发往 `wireguard_host:wireguard_port`，如果端口不对，WireGuard 收不到包。

```bash
# 在服务端查看 WireGuard 实际监听端口
wg show wg0 | grep "listening port"
# 输出示例: listening port: 51820

# 对比配置文件
grep wireguard_port /opt/hidewg/server.yaml
# 如果不一致，修正：
sed -i 's/wireguard_port: 51821/wireguard_port: 51820/' /opt/hidewg/server.yaml
```

### 10.6 服务端缺少 hidewg_app 模块

**症状**：服务端启动时报 `ModuleNotFoundError` 或 `ImportError`。

**原因**：服务端部署时只上传了部分文件，缺少 `hidewg_app/` 下的模块。

```bash
# 在服务端检查模块完整性
ls /opt/hidewg/hidewg_app/
# 必须包含以下文件：
# __init__.py  cli.py  config.py  protocol.py  adapter.py
# analysis.py  verify.py  state.py  pcap.py  transport.py  ws.py

# 从客户端补传
scp -r e:/safewg/hidewg_app root@1.95.65.51:/opt/hidewg/hidewg_app
```

### 10.9 性能过低

```bash
# 查看性能瓶颈
python -c "
import csv
with open('artifacts/performance_report.csv') as f:
    for row in csv.DictReader(f):
        print(f'{row[\"metric\"]:>30}: {row[\"value\"]:>15} {row[\"unit\"]}')
"
```

| 瓶颈 | 优化方案 |
|------|---------|
| 吞吐低 | 减少 `padding_buckets`，降低 `adapt_strength` |
| CPU 高 | 降低 `timing_jitter_ms`，关闭 `cover_traffic` |
| 带宽膨胀大 | 减少桶数量，降低桶值密度 |
